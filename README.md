## 執行方式

需求：Python 3.10 以上、Node.js、.NET 8 SDK（含 net8.0 目標套件與執行階段）、以及支援 `目前時間()`／`currentTime()` 的星泉 Wasm 編譯器（`aqua` 與隨附相依檔案）。不需要安裝 Python 套件或執行 npm install。星泉腳本使用星泉繁體中文版的繁體中文關鍵字與雙語內建函式，舊版僅支援英文的直譯器無法執行。

```powershell
python run_benchmarks.py
# 使用較小輸入，快速檢查正確性：
python run_benchmarks.py --profile smoke --repetitions 1 --warmups 0
# 使用較大輸入，降低 JIT 暖機的影響：
python run_benchmarks.py --profile large --timeout 300
# 必要時指定執行檔路徑：
python run_benchmarks.py --aquarius "C:\Aquarius\aqua.exe" --node "C:\Program Files\nodejs\node.exe" --dotnet "C:\Program Files\dotnet\dotnet.exe"
# 僅執行指定演算法：
python run_benchmarks.py --benchmarks fibonacci sieve matrix
# 使用既有資料重新產生 README，不重新測量：
python run_benchmarks.py --report-only results/latest.json
# 執行主控程式與參考答案測試：
python -m unittest discover -s tests -v
```

若 `python` 是尚未設定版本的 pyenv 代理程式，請直接呼叫已安裝的 `python.exe`。主控程式預設使用自身的 Python 直譯器執行測試，也可用 `--python PATH` 指定其他版本。它會搜尋目前程序的 PATH；在 Windows 上也會搜尋使用者與系統的最新 PATH，因此舊終端工作階段也能找到新加入的星泉路徑。執行環境參數只接受單一執行檔路徑。C# 會優先選用具有 SDK 的 dotnet，也會搜尋 DOTNET_ROOT 與使用者的 `.dotnet` 目錄；可用 `--dotnet PATH` 指定。

單獨執行 C# 測試（例如篩法）：

```powershell
dotnet run --project benchmarks/csharp/Benchmark.csproj --configuration Release -p:BenchmarkSource=sieve.cs
```

主控程式會在暫存目錄建立原始碼副本，只將 `benchmark_n` 的宣告替換為所選輸入規模。直接執行原始腳本時，採用標準規模。每次測量會建立帶有日期的 `results/` 子目錄，並重新產生 `results/latest.json` 與 `README.md`。可使用 `--output-dir`、`--readme`、`--timeout`、`--seed`、`--repetitions`、`--warmups` 自訂測試。結束碼 1 表示至少一個執行環境無法使用或測試驗證失敗；報告仍會保留失敗資訊。

## 測量方法

- 每筆樣本都啟動新的程序，但排名只採用腳本自行回報的 `ELAPSED_MS`。星泉使用 `目前時間()`（毫秒）、Python 使用 `time.perf_counter_ns()`（奈秒差值 ÷ 1e6）、Node.js 使用 `process.hrtime.bigint()`（奈秒差值 ÷ 1e6）。C# 使用 `Stopwatch.GetTimestamp()`（刻度差值 × 1000 ÷ Frequency）。所有計時器皆為單調計時器。
- 5 種語言皆在函式定義完成後、資料初始化前開始計時，並在演算法與校驗值計算完成後、輸出前停止。執行中的記憶體配置、垃圾回收及按需 JIT 仍計入。JSON／CSV 的 `elapsed_ms` 為程序內耗時；`process_elapsed_ms` 另保留完整程序耗時供診斷，不參與統計與排名。
- 星泉一律使用 `aqua build` 在測量前建立 Wasm，再執行 `aqua run`；Wasm 生成不計入樣本耗時。「星泉（型別）」使用同一個編譯器與相同演算法，只在變數、參數與回傳值加上選用型別標註（`benchmarks/aquarius_typed/`）；型別函式必須宣告回傳型別，因此快速排序與譜範數的原地修改函式多了一行 `回傳 0;`，二元樹的樹狀陣列無法標註，只標註計數變數。Python 執行原始碼，Node.js 使用 V8。C# 以 `dotnet build --configuration Release` 預先編譯為 net8.0 組件，再直接以 `dotnet Benchmark.dll` 執行；建置與還原不計時，不使用外部 NuGet 套件。進入 Main 前的初始 JIT 不計時，計時區間內的按需 JIT 仍計入。沒有 NumPy、原生演算法函式庫、工作執行緒或內建排序。
- 暖身程序的樣本會捨棄，作用是預熱作業系統檔案快取；不同程序之間不保留 JIT 或 VM 狀態。每輪以記錄的隨機種子打亂所有演算法／語言組合，再依序執行。
- 每筆暖身與正式樣本都必須符合未納入計時的 Python 參考答案。整數必須完全相同；譜範數平方的相對容許誤差為 1e-9，絕對容許誤差為 1e-12。非零結束碼、逾時、缺少或多餘的標準輸出、非有限數值、校驗值不符，都會使該測試失敗。計時輸出必須為有限且大於零的毫秒值；缺少計時值時不會退回程序外計時。
- 星泉的整數 `/` 會截斷小數，Python `//` 與 Node.js `Math.trunc` 使用相對應的運算。浮點測試採用雙精度（星泉使用 `d` 字面值）；標準輸入的整數中間值均在帶正負號的 32 位元範圍內。
- 陣列建構在各語言採用相同的線性成本：星泉使用 `陣列.建立` 預先配置（快速排序以預留容量的 `陣列.追加`），Python 使用 `[值] * n`／`append`，Node.js 使用 `push`，C# 使用 `new T[n]`（必要時 `Array.Fill`）；不使用每次複製整個陣列的追加方式。
- 編譯時機不對稱：星泉的 Wasm 在計時開始前已由 Wasmtime 完整編譯為機器碼；C#（分層編譯）與 Node.js（V8）的 JIT 編譯與最佳化發生在計時區間內。標準規模每項只需數毫秒，這部分成本偏向星泉；`--profile large` 以較大輸入降低此影響，兩種規模的分數不可混用。
- 小型工作負載可能受計時器與函式呼叫成本影響；每筆樣本使用新程序，未測量持續暖身後的穩態速度，也不代表所有程式的語言排名。CPU 頻率、溫度、背景工作與排程雜訊未受控制。未測量程序記憶體用量與 CPU 時間；下方 RAM 為機器配備。

## 正確性驗證

# 星泉、Python、Node.js 桌面執行效能評比

**本次綜合效能：Node.js 100.00 分、Python 16.84 分、星泉 16.50 分（越高越快）。**

綜合速度兩兩比較：Node.js 的綜合速度是 Python 的 5.94 倍；Node.js 的綜合速度是 星泉 的 6.06 倍；Python 的綜合速度是 星泉 的 1.02 倍。

將本次 10 項演算法的相對速度等權重取幾何平均，再以最快語言為 100 分。計時採用各語言程序內的單調計時器，涵蓋資料初始化與演算法／校驗值計算，排除程序啟動、原始碼／Wasm 載入與初始編譯、輸出。

表中速度倍率 = 該列語言綜合分數 ÷ 欄位基準語言綜合分數，使用未四捨五入的分數計算；大於 1 表示比該基準語言快，小於 1 表示較慢。

| 排名 | 程式語言 | 綜合分數 | 相對 Node.js 的速度 | 相對 Python 的速度 | 相對 星泉 的速度 |
| ---: | --- | ---: | ---: | ---: | ---: |
| 1 | Node.js | 100.00 | 1.000 倍 | 5.938 倍 | 6.062 倍 |
| 2 | Python | 16.84 | 0.168 倍 | 1.000 倍 | 1.021 倍 |
| 3 | 星泉 | 16.50 | 0.165 倍 | 0.980 倍 | 1.000 倍 |

相對速度 G = 幾何平均（各項 Python 耗時中位數 ÷ 該語言耗時中位數）；綜合分數 = 100 × G ÷ 三種語言中最大的 G，因此最高分固定為 100。每項演算法權重相同；只有三種語言在所有選定測試都通過時，才計算綜合分數。不同測試組合與輸入規模的分數不可直接比較。

本專案提供十種經典演算法、三十份可獨立執行的腳本，以及負責驗證結果、產生 README 與 JSON／CSV 報告的 Python 主控程式。

## 執行方式

需求：Python 3.10 以上、Node.js，以及支援 `目前時間()`／`currentTime()` 的星泉 Wasm 編譯器（`aqua` 與隨附相依檔案）。不需要安裝 Python 套件或執行 npm install。星泉腳本使用星泉繁體中文版的繁體中文關鍵字與雙語內建函式，舊版僅支援英文的直譯器無法執行。

```powershell
python run_benchmarks.py
# 使用較小輸入，快速檢查正確性：
python run_benchmarks.py --profile smoke --repetitions 1 --warmups 0
# 必要時指定執行檔路徑：
python run_benchmarks.py --aquarius "C:\Aquarius\aqua.exe" --node "C:\Program Files\nodejs\node.exe"
# 僅執行指定演算法：
python run_benchmarks.py --benchmarks fibonacci sieve matrix
# 使用既有資料重新產生 README，不重新測量：
python run_benchmarks.py --report-only results/latest.json
# 執行主控程式與參考答案測試：
python -m unittest discover -s tests -v
```

若 `python` 是尚未設定版本的 pyenv 代理程式，請直接呼叫已安裝的 `python.exe`。主控程式預設使用自身的 Python 直譯器執行測試，也可用 `--python PATH` 指定其他版本。它會搜尋目前程序的 PATH；在 Windows 上也會搜尋使用者與系統的最新 PATH，因此舊終端工作階段也能找到新加入的星泉路徑。執行環境參數只接受單一執行檔路徑。

主控程式會在暫存目錄建立原始碼副本，只將 `benchmark_n` 的宣告替換為所選輸入規模。直接執行原始腳本時，採用標準規模。每次測量會建立帶有日期的 `results/` 子目錄，並重新產生 `results/latest.json` 與 `README.md`。可使用 `--output-dir`、`--readme`、`--timeout`、`--seed`、`--repetitions`、`--warmups` 自訂測試。結束碼 1 表示至少一個執行環境無法使用或測試驗證失敗；報告仍會保留失敗資訊。

## 測量方法

- 每筆樣本都啟動新的程序，但排名只採用腳本自行回報的 `ELAPSED_MS`。星泉使用 `目前時間()`（毫秒）、Python 使用 `time.perf_counter_ns()`（奈秒差值 ÷ 1e6）、Node.js 使用 `process.hrtime.bigint()`（奈秒差值 ÷ 1e6）。三者皆為單調計時器。
- 三種語言皆在函式定義完成後、資料初始化前開始計時，並在演算法與校驗值計算完成後、輸出前停止。執行中的記憶體配置、垃圾回收及按需 JIT 仍計入。JSON／CSV 的 `elapsed_ms` 為程序內耗時；`process_elapsed_ms` 另保留完整程序耗時供診斷，不參與統計與排名。
- 星泉一律使用 `aqua build` 在測量前建立 Wasm，再執行 `aqua run`；Wasm 生成不計入樣本耗時。Python 執行原始碼，Node.js 使用 V8；沒有 NumPy、原生演算法函式庫、工作執行緒或內建排序。
- 暖身程序的樣本會捨棄，作用是預熱作業系統檔案快取；不同程序之間不保留 JIT 或 VM 狀態。每輪以記錄的隨機種子打亂所有演算法／語言組合，再依序執行。
- 每筆暖身與正式樣本都必須符合未納入計時的 Python 參考答案。整數必須完全相同；譜範數平方的相對容許誤差為 1e-9，絕對容許誤差為 1e-12。非零結束碼、逾時、缺少或多餘的標準輸出、非有限數值、校驗值不符，都會使該測試失敗。計時輸出必須為有限且大於零的毫秒值；缺少計時值時不會退回程序外計時。
- 星泉的整數 `/` 會截斷小數，Python `//` 與 Node.js `Math.trunc` 使用相對應的運算。浮點測試採用雙精度（星泉使用 `d` 字面值）；標準輸入的整數中間值均在帶正負號的 32 位元範圍內。
- 星泉的 `push`／`加入` 回傳新陣列並保留快照語意；目前 Wasm 執行階段可共用底層儲存，寫入時才視需要複製。Python 與 Node.js 對應的建構步驟使用複製後追加，因此其初始化可能包含平方級的複製成本。這組測試比較所列腳本的操作，不代表各語言慣用集合建構方式的最佳速度；慣用寫法另見診斷報告。
- 小型工作負載可能受計時器與函式呼叫成本影響；每筆樣本使用新程序，未測量持續暖身後的穩態速度，也不代表所有程式的語言排名。CPU 頻率、溫度、背景工作與排程雜訊未受控制。未測量程序記憶體用量與 CPU 時間；下方 RAM 為機器配備。
